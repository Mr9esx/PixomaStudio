# Studio 连续页面

## 页面结构

- 资产库：首页展示项目文件夹，搜索与新建项目位于同一操作栏。进入项目后显示资产，顶部面包屑返回文件夹首页，搜索和资产操作位于面包屑下方。工具栏「选择」开启多选，勾选控件位于名称区域。文件操作菜单位于名称同行，在悬停或键盘聚焦时显示，触屏保持可见；右键菜单提供下载操作。卡片直接打开主体内的大预览，属性面板使用 16px 内距、20px 分组间距；宽窗口并排显示，窄窗口上下排列。当前资产在文件树中展开并选中，支持按格式、分类等方式定位分组。详情页顶部保留重命名、用于创作和更多操作，支持放大、Escape 返回与焦点恢复。
- 工作流：列表使用开放式排列；编辑、版本内容、版本保存和运行表单位于主体内。运行输入和真实结果显示在同页。
- 技能：文件、基本信息和版本记录使用标签切换。保存版本与文件差异在当前页面展开，文件树、CodeMirror 和正文预览继续复用。
- 专家：提示词、工作方法、基本信息与版本记录使用页内标签；保存版本使用页内区域，编辑时保留 Studio 导航。
- 页面标题、工具栏和内容之间使用留白；主体表面、输入框和可调整面板保留必要边界。
- 未保存内容离开编辑页面时，提供继续编辑和放弃修改。
- 设置：通用、模型、技能、外部 MCP 服务和计算节点共用菜单。通用页提供对话数据清空，保留二次确认和资产库内容。

## 运行检查

设置项目内 `TMPDIR`、独立 `PIXOMA_STUDIO_DATA_DIR` 与空闲的 `PIXOMA_STUDIO_AGENT_LISTEN`。通过 `PIXOMA_LAYOUT_SCRIPT` 指向所需页面检查脚本，运行 `cargo run --manifest-path src-tauri/Cargo.toml --example native_layout`。

原生检查从 `/studio` 页面开始。检查窗口被隐藏时，通过检查程序恢复窗口焦点，让 WebKit 正常绘制交互和动画。

`native_integrated_pages.js` 使用新的独立数据库。`native_workflow_pages.js` 使用 `native_workflow` 保存的真实工作流数据库，继续验证编辑、版本和页面返回。
